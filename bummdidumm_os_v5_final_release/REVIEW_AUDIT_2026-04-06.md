### Gate 3 — Identity Consistency: PASS

Source identity is based on `file_id + sha256 + parser_name` (stable across renames
and moves). The following invariants are verified by tests:

- `test_rename_move_keeps_same_source_id` — rename/move does not create a new source
- `test_e2e_rename_no_duplicate` — rename produces one source, not two
- `test_e2e_no_temp_paths_leaked` — no `/tmp` paths persist as canonical `source_path`
- `id_builder.py` generates SHA256-based IDs from content, not file-system paths

The identity chain is consistent across Pass 1 → Pass 2 → sorting → apply sort →
rename → personal brain runtime → final JSONL index.

### Gate 4 — Incremental Safety: PASS

`personal_brain/writers.py` implements Read-Merge-Write for all JSONL outputs:

1. Load existing records from disk
2. Merge new records by ID (new wins on conflict, old records are preserved)
3. Write back atomically

Verified by:
- `test_incremental_merge_does_not_lose_previous_records` — prior records survive
  a partial re-index
- `test_idempotent_second_run_no_duplicates` — repeated runs do not inflate record
  counts

Delta page tokens in `state_helpers.py` allow resuming Pass 1 after interruption
without re-processing unchanged files.

### Gate 5 — Full-State Output Correctness: PASS

Master outputs (`CURRENT_personal_brain_search_view.jsonl`,
`CURRENT_personal_brain_master_index.json`, `CURRENT_personal_brain_summary.md`)
are built from the full merged on-disk state, not just the current batch.

`search_view_builder.py` reads the complete merged entity/record/relation indices
before writing the search view. `test_writers_output` validates output format
correctness.

### Gate 6 — Parser Safety: PASS

- `can_handle(preview)` in all parsers defensively checks preview type before
  accessing keys — the base class provides a safe default that returns `False` on
  type mismatches.
- Parser registry falls back to `GenericTxtExportParser` when no specific match is
  found.
- ZIP archive recursion in `source_ingestion.py` extracts to a temporary directory
  and passes the real extracted path to the parser; the temp path is cleaned up
  after parsing and is never persisted as `source_path`.
- `test_e2e_no_temp_paths_leaked` and `test_pipeline_e2e_rename_and_zip` confirm
  correct behaviour for ZIP sources.
- Path traversal in ZIP archives (`../../evil.json`) is neutralised by path
  sanitisation in `personal_brain/utils.py` and verified by
  `test_end_to_end_consistency`.

## 7. Non-Blocking Recommendations

1. **Add logging to `source_ingestion.py:76`** — the silent `except Exception: pass`
   in the JSON-preview path can mask unexpected read failures. A single `logging.debug`
   call would improve observability without changing behaviour.

2. **Add `requirements-dev.txt`** — listing `pytest` and `pre-commit` as dev
   dependencies improves environment reproducibility for contributors.

3. **Monthly dependency update cycle** — with upper bounds already in place, a
   monthly `pip-compile` run followed by this audit script would catch compatibility
   regressions early.

4. **Progressive stub implementation** — prioritise `parser_gmail_export` and
   `parser_signal_export` next, as they represent high-volume personal data sources.
